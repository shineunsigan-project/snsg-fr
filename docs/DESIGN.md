## 1. 서비스 전체 화면 구조

```
[진입]  로그인 ✅ ── 약관/개인정보처리방침(외부) ✅
          └─ 카카오 정보 제공 동의 (카카오 제공 화면, 구현 대상 아님) ── 최초 프로필 완성 ✅

[메인]  하단 GNB ✅
          ├─ 일정        : 일정 목록 ✅ → 일정 상세 ✅
          ├─ 일정 개설   : 1~5단계 입력 (미확인)
          └─ 내 정보     : 프로필 / 알림함 / 로그아웃 / 탈퇴 (미확인)

[오버레이]  로그인 필요 모달 ✅ · 필터 바텀시트 ✅ · 기타 확인/안내 팝업 📝
```

- ✅ 모든 화면 초안은 **모바일 단일 세로 프레임**이다(상단 iOS 상태바 `9:41`, 하단 홈 인디케이터 포함).
- ✅ GNB 3개 탭: `일정` / `일정 개설` / `내 정보`. 2026-10-11 시안부터 비로그인이면 세 번째가 `로그인`(§3.5).

## 3. 화면별 주요 UI 구성

### 3.1 로그인 ✅

```
┌──────────────────────────┐  배경: 브랜드 진녹색 전체
│        [대표 이미지]       │  ← 둥근 사각 placeholder (흰색)
│                          │
│ 쉬는시간                  │  ← 작은 라벨
│ 눈치 보느라 망설였다면,      │  ← 큰 제목 2줄 (흰색, Bold)
│ 이번엔 그냥 저질러보세요.     │
│ 사람 모아서, 하고 싶은 거 해보세요. │  ← 보조 문구
│                          │
│ [💬 카카오로 시작하기]       │  ← Kakao 노랑, 전체 폭
│ [   로그인 없이 둘러보기   ]  │  ← 흰 외곽선, 투명 배경
│ 로그인 시 개인정보처리방침↗ 및 │  ← 작은 안내문 + 외부 링크 2개(밑줄)
│ 이용약관↗에 동의하는 것으로 간주 │
└──────────────────────────┘
```

- ✅ 로그인 화면에는 GNB가 없다.
- `추정` 대표 이미지 영역은 실제 이미지로 교체될 자리다(`사진 DB는 서버에서 미리 준비` 메모).
- **대표 이미지 (2026-10-04):** 애니메이션 SVG `public/images/snsg-loop.svg`(원본 `SNSG무한반복.svg`, 248×220, 무한 반복)를 대표 이미지 상자 안에 비율을 유지해 넣는다. 애니메이션이 SVG 안의 SVGator 스크립트로 동작해 `<img>`가 아니라 `<object>`로 넣는다(`<img>`는 첫 장면에서 멈춤).

**최신 시안 (노드 `247:21229`, `loginpage.jpg`, 2026-10-04) — 위 구조와 다른 점**
- ✅ **`네이버로 시작하기` 버튼이 추가**됐다. 카카오 버튼 바로 아래, 네이버 녹색 배경 + 흰 `N` + 흰 글자 (팀 결정: 네이버 로그인 지원, TECH_STACK T-5).
- ✅ 대표 이미지 placeholder는 흰색이 아니라 **`bg.app`(아주 연한 회백색)** 이다.
- ✅ 하단 문구: "로그인 하시면 `개인정보처리방침`↗ 및 `이용약관`↗에 동의하는 것으로 간주됩니다" — **한 줄**, 링크는 흰색 Bold 밑줄 + 외부 링크 아이콘.
- ✅ 측정값 (390px 기기 폭 기준, 근사치 D-4)

  | 항목 | 값 |
  |---|---|
  | 좌우 여백 | 약 20px, 버튼·이미지 모두 전체 폭 |
  | 대표 이미지 | 약 347×280px, 모서리 약 20px, 상태바 아래 약 22px |
  | 라벨 `쉬는시간` | 약 15px, 연두색(`#B1D27B`), 이미지 아래 약 32px |
  | 큰 제목 | **28px Bold**, 줄 간격 약 40px, 흰색 |
  | 보조 문구 | 약 16px, 연한 녹백색(`#DFEBC7`) |
  | 카카오·네이버 버튼 | (시안) 높이 약 56px, 모서리 약 10px, 간격 약 16px, 아이콘 16px + 간격 12px + 16px Bold 라벨 → 구현은 공식 이미지로 대체 (아래) |
  | `로그인 없이 둘러보기` | 높이 약 52px, 흰색 30% 외곽선, 15px Bold 흰 글자 |
  | 하단 문구 | **11px**, 연한 녹백색, 화면 아래 홈 인디케이터 위 약 28px |

- 구현 (2026-10-04 수정): 대표 이미지 상자는 **화면 폭에 맞춘 5:4** 비율이다(휴대폰 폭 350px → 350×280 = 시안, 웹 최대 폭 408px → 408×326). 이미지와 문구 사이는 항상 32px이고, 화면이 길면 이미지부터 약관까지 묶음 전체를 **세로 가운데** 놓는다. 낮은 화면에서는 이미지 상자만 줄어들어 스크롤 없이 한 화면에 들어간다(iPhone SE 375×667에서 약 335×189). 애니메이션은 원본 비율(248×220)을 유지한 채 상자 안에 맞춘다. 제목·약관 안내는 단어 단위로 줄을 바꾼다. 태블릿·웹처럼 넓은 화면에서는 최대 폭 448px의 로그인 영역만 브랜드 녹색이고, 그 밖으로 늘어나는 양옆은 앱 기본 배경(`bg.app`, 홈 화면과 같은 색)이다.
- **팀 결정 (2026-10-04): 카카오·네이버 로그인 버튼은 코드로 그리지 않고 각 사가 제공한 공식 버튼 이미지만 쓴다.** "로그인" 글자가 들어간 이미지여야 하고, 심볼만 있는 이미지는 쓰지 않는다.
  - 카카오: `kakao_login_kr_large`(336×46, "카카오 로그인")를 버튼 폭에 맞춰 늘린다(약 350×48px).
  - 네이버: `NAVER_login_Dark_KR_green_center_H48`(368×48 표시 크기, PNG 4배 해상도, "N 네이버 로그인")을 같은 폭에 맞춘다(약 350×46px). 로그인 화면 배경이 어두운 녹색이라 Dark를 쓴다(Light와 사실상 같은 이미지).
  - 그래서 라벨이 Figma의 "카카오로 시작하기"·"네이버로 시작하기"가 아니라 **"카카오 로그인"·"네이버 로그인"** 이고, 버튼 높이가 시안(56px)보다 낮다.
  - 앱에서 쓰는 파일은 `public/images/kakao/`, `public/images/naver/`에 있다. 다른 크기·언어가 필요하면 원본을 다시 받는다(카카오: Kakao Developers 디자인 가이드, 네이버: 네이버 로그인 개발자 가이드 버튼 리소스).

## 12. Responsive

- ✅ 확인된 디자인은 **모바일 세로 프레임 하나**뿐이다. 태블릿·데스크톱·가로 모드 디자인은 없다.
- ✅ 상단 상태바와 하단 홈 인디케이터 영역이 디자인에 포함되어 있다.
  - `추정` 노치·홈바가 있는 기기의 안전 영역(safe-area) 대응이 필요하다.
- **서비스 형태 (팀 확인 2026-10-28, USER_FLOW §1):** MVP는 **웹앱**이다. 브라우저로 쓰거나 홈 화면에 추가해서 쓴다(홈 화면 추가 안내 ONB, USER_FLOW §9.1). 웹뷰 앱은 만들지 않는다(이전 "웹뷰 앱" 결정을 대신함, 2026-11-07 문서 정리). **모바일 세로 화면이 유일한 기준 화면**이다. 태블릿·데스크톱 대응은 MVP 범위가 아니다.
  - 홈 화면에 추가해 실행하면(standalone) 상태바와 홈 인디케이터 영역까지 화면이 그려지므로, 안전 영역(safe-area) 안에 맞춘다.
  - `추정` 공유 링크는 PC 브라우저에서도 열릴 수 있다. 이때 화면이 깨지지 않도록 모바일 폭으로 가운데 정렬하는 정도만 대응한다(D-3).
- `추정` 좁은 화면에서 주의할 부분:
  - 세그먼트 탭 3개와 필터 칩 3개가 넘칠 수 있다(값이 길어질 때, 예: `머더 미스터리·`).
  - 카드 제목이 길 수 있다(말줄임).

## 13. Figma에서 확인되는 디자인 규칙

1. ✅ **카카오 노랑 = 로그인 / 인증 관련 주요 액션.** 카카오 로그인 버튼과 로그인 필요 모달의 주요 버튼에 쓰인다.
2. ✅ **녹색 = 서비스 주요 액션과 활성 상태.** GNB 활성, 적용하기, 강조 배지, 날짜 텍스트에 쓰인다.
3. ✅ **2버튼 배치에서 주요 버튼이 오른쪽에 있고 더 넓다.**
4. ✅ **상태는 배지 색으로 구분한다.** 모집중은 연두, 모집완료는 회색, 남은 자리 강조는 진녹색이다.
5. ✅ **마감된 일정(모집완료)은 썸네일을 회색 톤으로 처리**해 시각적으로 약하게 만든다.
6. ✅ **날짜·시간은 녹색 작은 글자로 제목 위에 둔다.** 목록과 상세가 같다.
7. ✅ **가격 뒤에 결제 방식(`후불`)을 함께 표기한다.**
8. ✅ **로그인 필요 모달은 화면과 무관하게 동일한 디자인을 쓴다.**
9. ✅ **입력 필드 구조는 "라벨(위) → 입력 → 도움말(아래, 녹색)"** 이다.
10. ✅ **선택형 버튼의 선택 상태는 녹색 테두리 + 연두 배경 + 녹색 Bold 글자**로 표현한다(성별 토글).
11. ✅ **전체 화면형 입력 단계(로그인, 프로필 완성)는 GNB 없이 하단에 전체 폭 CTA 하나**를 둔다.

## 14. 개발 시 디자인상 주의사항

- **색상·간격·radius 수치는 모두 근사치 또는 미확인이다.** 하드코딩하지 말고 토큰으로 한곳에 모아 두어야 나중에 교체하기 쉽다.
- **대표 사진은 "보류" 상태다.** 이미지가 없을 때의 placeholder(사선 패턴)를 기본 상태로 다뤄야 한다.
- **카드는 3줄(태그 줄·제목·정보 줄)로 고정이다.** 긴 제목은 말줄임한다.
- **목록 헤더가 두 가지 버전(로고 / 타이틀 `일정`)으로 섞여 있다.** 확정 전에는 둘 다 수용할 수 있게 만든다.
- **필터 칩은 시각 상태가 3가지다.** 기본, 값 선택됨, 시트 열림을 각각 구분해야 한다.
- **카카오 동의 화면은 구현하지 않는다.** 카카오가 제공하는 화면이다(팀 확인).
- **이메일 필드는 프로필 완성과 프로필 수정 둘 다에 둔다(2026-10-22, 기능 요구사항 정의서 v0.3).** 2026-10-04 "프로필 수정에만" 결정을 대신한다.
- **프로필 완성 화면에는 뒤로가기·GNB가 없다.** 이탈 방법이 디자인에 없다는 점을 유의한다(USER_FLOW F-13).
- **Loading, Error, 대부분의 Empty 디자인이 없다.** 임의로 디자인하지 말고 확인 후 구현한다.
- **보드에 오래된 와이어프레임이 함께 있다.** 참고할 때는 "쉬는시간 MVP 화면 초안" 이미지만 기준으로 삼는다.
