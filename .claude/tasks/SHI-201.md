## 기획 내용 (v1.5 27쪽 정리)
- 진입: MY-01 `참여 이력 ›`. 뒤로 `‹` → MY-01.
- 목록: 지난 일정(일정 완료 · 일정 취소됨) 중 참여한 일정과 개설한 일정을 한 목록에 섞어서, 시작 시간 최근 순.
- 카드: 활동 카테고리 · 상태 배지(일정 완료 / 일정 취소됨) · 역할 배지(참여 / 개설) · 활동명 · 지역 · 약속 시간(회색) · 확정/전체 인원. D-n · n자리 남음 · NEW는 없다.
- 목록 위: `지난 일정 n · 최근 순`.
- 20개씩, 목록 끝에 닿으면 다음 20개.
- 0개: `아직 지난 일정이 없어요`.
- 참여를 취소한 일정은 나오지 않는다. 내가 전체 취소한 일정은 `일정 취소됨 · 개설`로 나온다. 같은 일정이 참여·개설로 두 번 나오지 않는다.
- 카드 탭: 참여한 일정 → DTL-05(버튼 비활성 + 상태명), 개설한 일정 → HOST-01(일정 전체 취소 비활성 + 상태명). `일정 취소됨` 카드는 상세 위에 취소 사유 시트가 열린다(이 이슈에서는 만들지 않는다).
- MY-01: 프로필 아래 `참여 이력 ›` 한 줄, 그 아래 이용약관 ↗ · 개인정보 처리방침 ↗ · 로그아웃 · 회원 탈퇴. 다가오는 일정은 이 화면에 없다.

## API 확인 (snsg-be develop `96f6cee`, 2026-11-23)
- `GET /api/v1/schedules/participating?period=PAST`, `GET /api/v1/schedules/hosted?period=PAST`. 각각 시작 늦은 순(같으면 id 역순), `cursor`·`size` 커서 방식, 로그인 필요(401).
- 참여한 목록은 내가 연 일정을 뺀다. 그래서 두 목록을 합쳐도 겹치지 않는다. 참여 취소한 일정도 뺀다.
- 개설자가 취소한 일정은 완료 시각(시작 + 12시간) 뒤에 `CANCELED`로 지난 일정에 온다. 완료된 일정은 `COMPLETED`.
- 목록 항목에는 역할 필드가 없다. 어느 목록에서 왔는지로 역할을 정한다.
- 총 개수 필드가 없다(`nextCursor`만 있다).
- api-guide는 "두 결과를 한 목록에 섞지 않는다(정렬 방향이 반대다)"고 쓰지만, 이는 다가오는 일정(빠른 순)과 지난 일정(늦은 순)을 섞지 말라는 뜻이다. 지난 일정끼리는 정렬 방향이 같아 섞을 수 있다.
- 두 목록을 합쳐 주는 API는 없다.

- 2026-11-23 (사용자) `지난 일정 n`의 n은 지금까지 불러온 개수다.
- 2026-11-23 (사용자) 시안 두 장을 열어도 된다고 허락했다. 시안 확인: 내 정보는 프로필 카드 → `참여 이력 ›` → 약관·로그아웃·탈퇴 카드, 참여 이력은 `‹ 참여 이력` 제목줄 + 상태·역할 배지가 있는 카드.
- 2026-11-23 (사용자) 취소 사유 시트(DTL-05-1·HOST-01-2)는 보류한다. 이번 수정 사항(내 정보·참여 이력)에 없었다. 취소된 일정 카드를 누르면 상세로만 간다. 구현할 때는 상세 응답의 `cancellation`(사유·일시)이 이미 오고, 참여 이력 카드에 `?from=history`를 붙여 진입 경로를 구분하는 안을 쓴다. 기존 결정 F-20(취소 사유는 상세에 보이지 않는다)도 그때 함께 정한다.
