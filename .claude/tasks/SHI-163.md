## 실제 계약 요약 (api-guide e746440)

| 탭 | 경로 | 인증 |
|---|---|---|
| 모집 중 | `GET /api/v1/schedules` | 필요 없음 |
| 참여한 일정 | `GET /api/v1/schedules/participating` | 필요(401 `UNAUTHENTICATED`) |
| 개설한 일정 | `GET /api/v1/schedules/hosted` | 필요 |

- 쿼리: 모집 중만 `categoryIds`(활동 UUID, 반복), `regionCodes`(5자리, 반복), `startDate`·`endDate`(`yyyy-MM-dd`). 세 목록 모두 `cursor`, `size`(기본 20, 최대 50). 참여한·개설한은 필터를 받지 않는다(보내도 무시).
- 응답 `data`: `{ items: [...], nextCursor: string | null }`. 마지막 페이지면 `nextCursor` null.
- item: `id`, `category { id, name }`, `title`, `regionName`, `startAt`, `confirmedCount`, `capacity`, `remainingSeats`, `displayStatus`, `createdAt`. 모두 null 아님. `category.name`·`regionName`은 정보가 없으면 빈 문자열.
- `displayStatus`: `RECRUITING` / `RECRUITMENT_CLOSED` / `CANCELED`(참여한·개설한만) / `COMPLETED`(목록엔 오지 않음).
- 정렬: 세 목록 모두 시작 일시 빠른 순, 같으면 id 순. 참여한·개설한은 **완료(시작 + 12시간) 전 일정만** 온다. 지난 일정 API는 없다.
- 다음 페이지: 같은 파라미터에 `cursor=<nextCursor>`만 붙인다. 필터·탭을 바꾸면 cursor 없이 처음부터. 중복·누락 없음.
- 오류: 400 `INVALID_DATE_FILTER`(end < start), 400 `INVALID_CURSOR`(cursor 없이 처음부터 다시), 400 `INVALID_REQUEST`, 401 `UNAUTHENTICATED`(참여한·개설한).

- **NEW 배지: 개설 후 24시간 안**(`createdAt` 기준, 사용자 결정 2026-11-10). 위의 "숨긴다"를 대신한다.
- **목록 내용·순서·상태는 서버가 주는 대로 (사용자 결정 2026-11-10):**
  - 참여한·개설한 탭: 완료 전 일정만, 시작 빠른 순. 정의서의 "지난 일정(완료·취소)을 아래에 시작 최근 순"은 하지 않는다(지난 일정 API 없음).
  - 시작했지만 완료 전인 일정: 서버 `RECRUITMENT_CLOSED` 그대로(목록에 "활동 진행 중" 표시 없음). 상세의 활동 진행 중은 SHI-164에서.
  - 모집 중 탭: 시작 시각이 같으면 서버 순서(id 순) 그대로. 화면에서 다시 정렬하지 않는다.
  - **취소된 일정(`CANCELED`) 카드에 `일정 취소됨` 태그**(api-guide 안내). 참여한 탭은 참여 확정·D-day 대신, 개설한 탭은 상태 태그 자리에. USER_FLOW의 F-21 "취소는 상태 태그 없음"을 고친다.
- 지역 필터는 지금처럼 하나만 고른다(팀 결정 2026-11-02). 서버에는 `regionCodes=<값>` 하나로 보낸다. 활동도 `categoryIds=<값>` 하나.
- 상태 값 `CLOSED` → 서버 이름 `RECRUITMENT_CLOSED`로 바꾼다(`features/schedule/types.ts`, 상세·MSW·e2e 포함). `IN_PROGRESS`는 상세(SHI-164)에서 정할 때까지 그대로 둔다.
- 목록 item 타입은 서버 필드 이름을 그대로 쓴다(변환 코드 없음).
