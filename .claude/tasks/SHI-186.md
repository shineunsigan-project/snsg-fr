# SHI-186 로그인 후 뒤로·앞으로 가기에서 로그인 화면이 끼어듦

## 개요
SHI-185 배포 후, 로그인 뒤 상세에서 뒤로가기를 하면 확인 중 초록 화면이 보이고, 앞으로 가기를 하면 로그인 화면에 닿았다가 튕겨 나온다(AUTH-01). 방문 기록에 로그인 화면이 남기 때문이다. 다른 서비스처럼 로그인 상태면 화면을 그리기 전에 서버에서 이동시키고, 로그인 화면이 기록에 남지 않게 한다. 상위 SHI-150, SHI-185 후속.

## 기준 문서
- USER_FLOW §4.2, TECH_STACK §6, `.claude/rules/api.md` 상태 위치
- 다른 서비스 조사(2026-11-15): 로그인 상태 판별은 대부분 서버(미들웨어)에서 화면을 그리기 전에 한다(Auth.js·Authgear·WorkOS 안내). 화면에서 할 때는 빈 화면(Clerk 기본)이나 로딩 표시(`<ClerkLoading>`). 오버레이 사례는 없음
- Next.js 16 `proxy.ts`(node_modules/next/dist/docs 03-file-conventions/proxy.md)

## 결정 사항 (사용자 결정 2026-11-15)
- 로그인 표시용 쿠키 `snsg_logged_in`(앱 주소, 14일, 인증에는 쓰지 않음)을 `setAccessToken`이 토큰과 함께 맞춘다. `src/proxy.ts`가 `/login` 요청에서 이 쿠키가 있으면 307로 홈에 보낸다
  - 로그인 쿠키(refresh token)는 API 서버 주소(`Path=/api/v1/auth`)라 앱 서버가 볼 수 없어서다. 백엔드가 직접 내려 주는 방식은 범위 밖(기록만)
- 로그인 화면에서 카카오로 갈 때 `location.replace`로 방문 기록의 로그인 화면을 바꾼다. 카카오에서 뒤로가기하면 로그인을 누른 화면으로 간다(USER_FLOW §4.2 문구 변경)
- 뒤로가기 캐시(bfcache) 복원 시 앱 전체(`providers.tsx`)에서 로그인 상태를 먼저 다시 받고, 나머지 쿼리를 무효화한다. SHI-185의 "로그인 화면만 새로 불러오기"를 대신한다
- 확인 중 로그인 화면: 이미지·문구는 그대로, 버튼만 `invisible`(자리 유지)
- 화면 안의 로그인 상태 확인(앱 안이면 앞 화면, 아니면 홈)은 표시용 쿠키가 없을 때의 안전장치로 남긴다

## 사이드 이펙트 검토
- 표시용 쿠키가 실제와 어긋남(서버에서 refresh 만료·탈퇴 처리): `/login` → 홈으로 한 번 헛걸음, 홈의 복구가 401이면 `setAccessToken(null)`로 지워져 다음엔 로그인 화면이 보인다(E2E)
- 반복 이동(루프): 로그인 화면으로 보내는 모든 경로가 이동 전에 쿠키를 지운다. 재발급 실패 인터셉터·탈퇴·404 clearSession·USER_NOT_ACTIVE는 `setAccessToken(null)`, 콜백 실패·가입 세션 만료(restartLogin)는 명시적으로 `setAccessToken(null)`, 로그인 버튼들(헤더·탭·상세·개설·내 정보)은 `saveLoginRedirect`가 지운다(리뷰 반영: 복구가 네트워크 오류·5xx면 예전 쿠키가 남아 로그인 버튼이 홈으로 튕기던 것을 E2E로 재현 후 수정)
- 앱 안 이동(`router.push("/login")`)도 RSC 요청이 proxy를 지나므로 같은 판단을 받는다. 로그인 상태에서 로그인 화면으로 push하는 곳은 없다
- bfcache 복원마다 로그인 재발급 1번 + 활성 쿼리 다시 받기가 생긴다(네트워크 비용 작음)
- 로그인 전 상세는 로그인 화면 기록을 바꿔치기해서 뒤로가기 캐시에 남지 않고 새로 불러와진다(E2E에서 확인)
- 주소를 직접 열어 로그인 화면에 온 경우는 기록을 바꾸지 않는다(`canGoBackInApp()`일 때만 replace). 바꾸면 카카오에서 뒤로가기할 때 사이트 밖으로 나가기 때문(사용자 결정 2026-11-15, E2E)
- Safari ITP는 `document.cookie`로 만든 쿠키를 최대 7일로 줄인다. 8~14일 사이는 화면의 안전장치가 처리한다(루프 없음)
- 로그인 필요 모달(`LoginRequiredDialog`)은 지금 쓰는 화면이 없다. bfcache 앱 전체 처리는 약관 등 다른 페이지에 다녀온 경우에 쓰인다
- 로그인한 사람이 주소로 `/login`을 열면 서버는 정해진 주소(홈)로만 보낼 수 있다(복귀 경로는 sessionStorage라 서버가 못 봄). 홈으로 보내는 것은 사용자 확인(2026-11-15)
- 로컬 http에서는 Secure를 붙이지 않는다(Safari가 http://localhost Secure 쿠키를 저장하지 않음)
- Vercel에서 `/login` 요청만 proxy 함수가 실행된다(matcher `/login`)
