# SHI-185 로그인 후 뒤로가기하면 로그인 화면이 다시 보임

## 개요
로그인 후 상세에서 뒤로가기를 하면 방문 기록에 남은 로그인 화면(AUTH-01)이 다시 보인다. 로그인한 사람이 로그인 화면에 오면 바로 내보낸다. 네이버 인증이 아직 연결되지 않아 네이버 버튼을 숨긴다. 상위 이슈 SHI-150.

## 기준 문서
- USER_FLOW §4.2 (로그인 화면), DESIGN §3.1 (로그인 화면 시안)
- 다른 서비스 조사: Clerk `<SignIn />`(로그인 상태면 홈으로), 라우터 공통 패턴(로그인 화면 guest 가드 + replace)

## 결정 사항
- 2026-11-15 로그인 상태면 로그인 화면을 내보낸다. 앱 안에서 왔으면 앞 화면(`router.back`), 아니면 홈(`router.replace("/")`). 저장한 복귀 경로로는 보내지 않는다(같은 화면이 기록에 반복됨)
- 2026-11-15 로그인 여부 확인 중에는 버튼 없이 녹색 배경만 보인다(버튼 깜빡임 방지)
- 2026-11-15 처음에는 내보내기만 하기로 했으나, 배포 화면에서 겪은 흐름(홈 → 상세 → 로그인 → 카카오 → 상세 → 뒤로가기)은 브라우저가 뒤로가기 캐시(bfcache)로 로그인 전 로그인 화면을 복원해 내보내기가 동작하지 않음을 E2E로 재현. 다른 서비스 사례(① 복원 시 상태만 다시 확인 / ② 복원 시 새로 불러오기 / ③ `no-store`) 비교 후 ②를 로그인 화면에만 적용(사용자 결정). ③은 앱 안 이동이라 처음 연 문서(`/`, `public, max-age=0`) 기준이어서 맞지 않고, ①은 앱 전체 범위라 나중에
- 다른 화면(일정 상세 등)의 복원 시 데이터 다시 받기(①)는 범위 밖
- 2026-11-15 네이버 로그인 버튼 숨김(연결 전, TODO(T-5))
- `canGoBackInApp`을 두 기능에서 쓰게 되어 `shared/lib/navigation.ts`로 옮김
