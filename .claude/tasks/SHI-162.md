# SHI-162 일정 개설을 실제 API로 연결 (활동 목록·장소 후보·일정 열기)

상위: SHI-151 (일정 개설). Linear: https://linear.app/shineunsigan/issue/SHI-162 · 브랜치 `feature/SHI-162-schedule-create-api` (develop 기준, 작업 폴더 `../snsg-fr-151`)

## 개요

일정 개설(CRT-01·02·06·07)을 임시 계약·네이버 검색에서 백엔드 실제 API로 바꾼다 (snsg-be api-guide, develop b873383). 일정 목록의 활동 필터 쪽 변경은 SHI-152에 넣는다.

## 범위

* **활동 목록:** `GET /api/v1/activity-categories` (`id` UUID, `code`, `name`). 활동 ID를 숫자에서 UUID 문자열로
* **장소 선택 (CRT-02):** 네이버 검색 Route Handler(`/api/places`)를 지우고 `GET /api/v1/place-candidates`로. `전체` 칩은 `regionCode`를 빼고 부른다(F-18 해결). 주소는 도로명주소 + 상세주소. `INVALID_CATEGORY`·`INVALID_REGION` 처리
* **일정 열기 (CRT-06):** `POST /api/v1/schedules` 실제 계약(`categoryId`, `placeId`, `durationType` SHORT/NORMAL/LONG, 201 + `scheduleId` UUID). 칸별 오류(`errors`)와 `INVALID_CATEGORY`·`INVALID_PLACE`·`INVALID_START_AT`·`INVALID_CAPACITY`·`USER_NOT_ACTIVE` 처리
* **입력 기준을 서버와 맞춤 (사용자 결정 2026-11-08):** 시작 날짜 오늘 + 30일까지(달력 제한), 활동명·설명 글자 수를 코드 포인트로(이모지 1자)
* **개설 완료 팝업 (CRT-07):** 없는 API(`/schedules/{id}/created`) 대신 고른 장소명을 넘긴다
* MSW·e2e·USER_FLOW·`.env.example`(네이버 검색 키 제거)
