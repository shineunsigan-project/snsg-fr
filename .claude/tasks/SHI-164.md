# SHI-164 일정 상세·참여를 실제 API로 연결

상위: SHI-155 (일정 상세·참여). Linear: https://linear.app/shineunsigan/issue/SHI-164 · 브랜치 `feature/SHI-164-schedule-detail-api` (develop 308cb59 기준)

## 개요

일정 상세·참여자 명단·참여·참여 취소·일정 전체 취소(DTL-01~08, HOST-01~02)를 임시 계약·MSW에서 백엔드 실제 API로 바꾼다. 기준: snsg-be api-guide develop `e746440`.

- USER_FLOW §7, DESIGN 상세 절, 지시서 SHI-155(상세 화면 결정)

## 실제 계약 요약 (api-guide e746440)

| API | 경로 | 인증 |
|---|---|---|
| 상세 | `GET /api/v1/schedules/{id}` | 선택(없으면 `GUEST`, 틀려도 401 없음) |
| 참여자 명단 | `GET /api/v1/schedules/{id}/participants` | 필요. `HOST`·`PARTICIPANT`만(그 밖 403) |
| 참여 | `POST /api/v1/schedules/{id}/participants` | 필요 |
| 참여 취소 | `DELETE /api/v1/schedules/{id}/participants/me` | 필요 |
| 일정 전체 취소 | `POST /api/v1/schedules/{id}/cancellation` `{ reason }` (1~100자) | 필요, 개설자만 |

- 참여·참여 취소·일정 취소 뒤에는 성공이든 실패든 상세를 다시 불러 그린다.
- 버튼 활성은 상세의 `availableActions`(`LOGIN_TO_JOIN`·`JOIN`·`CANCEL_PARTICIPATION`·`CANCEL_SCHEDULE`)로 정한다.

## 결정 사항

사용자 결정 2026-11-11 (열린 질문 번호 기준):

1. **활동 진행 중 없앰 — 서버대로.** 시작 후 ~ 완료 전은 `RECRUITMENT_CLOSED`(태그·비활성 문구 "모집 마감"). `IN_PROGRESS` 타입·`in-progress` 버튼 변형·Story를 지운다. startAt으로 계산하지 않는다
2. **참여 취소는 완료 전까지 — 서버대로.** `availableActions`에 `CANCEL_PARTICIPATION`이 있으면 시작 후에도 활성
3. **일정 취소 뒤 참여 기록 유지 — 서버대로.** 참여자는 계속 PARTICIPANT, 인원·명단 유지. **USER_FLOW에 기획(정의서 v0.3 "미참여자로 전환")과 백엔드가 다르다는 점을 기록**
4. **취소 사유 1~100자 — 서버대로**(앞뒤 공백 제외, 이모지 1자)
5. **취소 사유(`cancellation`)는 상세에 보여주지 않는다.** 알림 기능(F-20)이 생기면 그때 보여준다
6. **참여자 요약 겹친 아바타는 연두색 원으로만**(아이콘 없이, 시안처럼) min(인원, 4)개. 서버가 사진 목록을 주지 않는다 → **바뀜(2026-11-11, 실제 서버 확인 후):** 개설자·확정 참여자는 상세를 열 때 명단도 받아 앞쪽 사진 최대 4장. 조회자·미참여자(명단 403)와 명단을 받기 전은 연두 원. 대가: 개설자·참여자는 상세마다 명단 요청 1번 더
7. **사진은 서버가 주는 이미지를 그대로 쓴다.** 서버 기본 이미지(`/images/default-profile.png`, 회색)도 바꾸지 않는다. 경로가 상대 경로라 서버 주소를 앞에 붙인다
8. **409 안내는 서버 `message`를 토스트로**(📝 임시 문구 대신)
9. **시작 후 개설자 버튼 → 기획대로 비활성 + 상태명 `⊘ 모집 마감`**(정의서 194·1021·1174행 "모집 중·모집 마감일 때만", "불가 상태는 비활성 + 상태명"). 토스트 없음. `availableActions`에 `CANCEL_SCHEDULE`이 없으면 비활성
10. **일정 취소 5xx·네트워크 오류 → 기획대로 시트와 입력한 사유를 유지**하고 다시 누를 수 있게 한다(화면 명세 공통 예외 "5xx·네트워크 → 화면 유지 + [다시 시도]")
11. **사유가 비면 [확인]만 막는다**(정의서 1022행 "비어 있으면 진행할 수 없다", 안내 문구 없음). 글자 수 표시는 `/100`
- **참여 성공 토스트 "참여가 확정되었어요"(2초) 추가**. 기획(DTL-03 "버튼 → 참여 취소, 인원 +1")에 안내가 없지만 버튼만 바뀌는 게 어색하다(사용자 결정 2026-11-11, 📝 TODO(F-19))
- **확인 팝업 문구는 시안 그대로**("확정 참여자 N명의 참여가 모두 취소되고, 취소한 일정은 되돌릴 수 없어요."). 서버는 참여 기록을 남기지만 참여자 입장에서 모임이 없어진 것이라 뜻이 통한다(사용자 결정 2026-11-11)

- 바로 고침(질문 없이): 필드 이름·`/cancellation` 경로·code로 판정·결과와 상관없이 상세 다시 불러오기·시작 후 개설자 취소 버튼 비활성(`availableActions`)·참여 취소 실패 문구·로그인했는데 GUEST면 재발급 후 다시 부르기

## 열린 질문

requirements-analyst 대조 2026-11-11 (35항목: 반영 7·부분 6·미반영 13·충돌 3·확인 필요 6). 기획과 API가 다른 것:

1. 활동 진행 중 — 정의서·시안 DTL-08·F-21에는 있고 API엔 없음(시작 후 ~ 완료 전은 `RECRUITMENT_CLOSED`). 시작 여부는 startAt 계산뿐(서버 판정 규칙 위반)
2. 참여 취소 가능 시점 — 정의서·USER_FLOW §7.4 "활동 진행 중 이후 불가" vs API 완료 전까지 가능(시작 후 취소는 모집 재개 안 함)
3. 일정 취소 뒤 — 정의서·USER_FLOW §7.5 "확정 참여자를 미참여자로" vs API 참여 기록·인원·명단 유지, 역할 PARTICIPANT
4. 취소 사유 길이 — 정의서·USER_FLOW 1~200자 vs API 1~100자
5. 취소 사유 상세 표시(`cancellation`) — 기획·시안에 없음, API는 누구에게나 줌
6. 참여자 요약 겹친 아바타 — 시안·Q6 있음, API에 사진 목록 없음
7. 탈퇴한 개설자(상단) 표시 — 기획 규칙 없음, API `host.withdrawn`
8. 409 안내 문구 — 📝 임시 문구(F-19) vs 서버 `message`
9. 비활성 버튼 문구(예: 시작 후 개설자 `availableActions` 빈 배열)
10. 일정 취소 5xx — 시트 유지 vs 닫기(가이드 모호)
11. 사유 검증 문구 — 비었을 때 [확인]만 막기 vs "취소 사유는 1~100자로 적어주세요."
