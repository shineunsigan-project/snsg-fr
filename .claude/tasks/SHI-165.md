사용자 결정 2026-11-12 (열린 질문 번호 기준, 대조 기준 snsg-be develop e746440):

1. **탈퇴 순서는 서버·화면 명세대로: 가능 여부 조회 → 재확인 → 탈퇴.** [회원 탈퇴] → `GET /users/me/withdrawal-eligibility`(응답 전까지 [회원 탈퇴] 막음) → `withdrawable` false면 불가 팝업, true면 재확인 팝업 → `DELETE`. 조회 실패(5xx·네트워크)는 기존 임시 토스트 "탈퇴하지 못했어요. 다시 시도해주세요."(F-19)
2. **불가 팝업은 시안 문구만**("진행중인 일정이 있습니다." + "모든 일정을 취소하거나, 마지막 일정 시작 시각으로부터 24시간이 지나야 탈퇴할 수 있어요."). `availableAt`은 보여주지 않는다(api-guide는 안내하라고 함 — 기획대로)
3. **재확인 뒤 `DELETE`가 409 `WITHDRAWAL_BLOCKED`면** 재확인 팝업을 닫고 2번과 같은 불가 팝업(시안 문구). 서버 `message`는 쓰지 않는다
4. **닉네임 사용 가능 여부 API를 가입(AUTH-03)·프로필 수정(MY-02) 둘 다 붙인다.** 닉네임 칸을 벗어날 때, 화면 형식 검사를 통과했을 때만. MY-02는 지금 닉네임과 같거나 잠금 중이면 부르지 않음, 가입은 카카오 닉네임 그대로여도 부름. 문구는 USER_FLOW §4.1 표 그대로("사용할 수 있는 닉네임이에요." 녹색 / 중복 빨강 / 요청 실패 빨강)
5. **[시작하기]·[수정 완료] 때는 사용 가능 여부를 다시 부르지 않는다.** 바로 저장 요청하고, 중복이면 가입·수정 API의 409 `DUPLICATED_NICKNAME`으로 칸 아래 같은 문구(지금 코드 유지). USER_FLOW 212행 "누르면 닉네임 중복을 검사한다"는 "저장 API의 409로 검사"로 고친다
7. **MY-02 닉네임 안내는 기획대로**: 처음·입력 중에는 "닉네임을 바꾸면 14일 동안 다시 바꿀 수 없어요."(시안 MY-02), 칸을 벗어나 확인하면 그 자리에 결과 문구(사용 가능 녹색·중복/실패 빨강, 화면 명세 MY-02 "AUTH-03 규칙"), 값을 고치면 다시 14일 안내. 두 문장을 함께 두는 안(인스타그램 방식·`TextField` `note`)은 어색해서 되돌림 — 리뷰 권장 1 종결 (사용자 결정 2026-11-12)
6. **MY-02 연령대는 서버 `ageGroup`으로.** MY-01은 기획·시안대로 연령대 없음
