# 한국어 글쓰기

Linear 이슈, 커밋 본문, PR 본문, 아티팩트(페이지 문구)를 쓸 때 적용한다. 코드, 인용, 식별자(`SHI-<번호>`, 파일명, 함수명)에는 적용하지 않는다. 어투는 기존 문서처럼 "~한다"를 유지한다. 단 PR 본문과 Linear 이슈 본문은 아래 "명사형 항목에 이유를 덧붙여 쓰기"를 따른다.

[fluent-korean](https://github.com/snflkd/fluent-korean)(MIT) 지침 중 필요한 것만 줄여 왔다.

- **문장 성분을 생략하지 않는다.** 특히 '~의'를 겹쳐 쓰면 뜻이 빠지기 쉽다. 예: "카드의 뱃지의 규칙" → "카드에 표시하는 뱃지 규칙"
- **본문 문장은 서술어와 종결어미로 끝낸다.** 명사구·연결어미로 끝내지 않는다. 헤더와 목록 항목, PR·Linear 본문은 예외.
- **조사와 어미를 생략하지 않는다.** 예: "탭 전환 시 재요청" → "탭을 전환하면 목록을 다시 요청한다". PR·Linear 본문의 명사형 항목은 예외.
- **비유적 어휘를 일반 어휘로 바꾼다.** 예: "코드로 박는다" → "코드에 명시한다", "렌즈·축" → "관점·기준"
- **엠대시(—)를 쓰지 않는다.** 콜론이나 접속사로 바꾼다.
- **기술 용어:** 통용되는 번역어가 있으면 쓰고, 없으면 원어를 그대로 둔다.
- **명사형 항목에 이유를 덧붙여 쓰기: PR 본문과 Linear 이슈 본문은 명사형 항목으로 쓰되, 항목마다 이유·영향·확인한 것을 한두 문장 덧붙인다**(사용자 결정 2026-11-23 명사형, 2026-11-25 "너무 짧다"는 피드백으로 설명 보강). 한 줄에 사실 하나를 두고 줄 끝은 명사형으로 맺되, 무엇을 했는지만 던지지 않고 왜 그렇게 했는지와 어디에 영향이 가는지를 `항목: 이유·영향` 형태로 풀어 쓴다. 예: "배경색 제거: 이미지 위에서 글자가 묻혀 읽기 어려웠고, 모든 카드가 같은 문제라 공통 컴포넌트에서 한 번에 처리". 결정에는 이유와 날짜, 확인에는 실행한 검사와 못 본 것, 남은 결정에는 누가 정해야 하는지를 적는다. 절 구성(PR: 작업 내용·결정·임시 계약·확인·남은 결정·대조한 API, 이슈: 개요·범위·범위 밖)은 그대로 둔다. 커밋 본문은 문장형을 유지한다.
